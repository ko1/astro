3 日以内の計測 4〜10 日 それより古い。 各値に計測日・commit・実行モード（interp = tree-walking インタプリタ、AOT = 事前コンパイル）を付けている。最新とは限らない。

互換性（CRuby と同じに動くか）

gem ごとのテスト — CRuby と koruby で同じテストファイルを流し、結果の要約行（例の数・失敗数・エラー数）が一致するか

CRuby でも落ちるテストを koruby が同じように落とすのも一致に数える。不一致の gem は名前をクリックするとファイルと両者の結果が出る。 目標は gem を増やすことと不一致を減らすこと。

健全性（壊れていないか）

make test の不一致（CRuby master と出力が違う行）

性能

optcarrot fps（180 frame、中央値、高いほど速い）

rubybench の網羅 — 目標: github.com/rubybench/rubybench の全ベンチを koruby で動かして測る

ruby-bench のベンチごとの結果 — 1 反復の時間（ms、10 反復の平均、sp4 専有）。比は小さいほど koruby が速い

koruby interp = インタプリタ（--plain）。koruby AOT = ベンチごとに事前コンパイルしてから実行した時間（コンパイル時間は含まない）。 AOT コンパイル時間 = --pg-compile 1 回の実時間（ベンチを 1 反復走らせ、SD を C に書いて gcc でビルドするまで。preload は焼き済み。ccache が有効なので、前の計測で同じ C を焼いていたものは短く出る。例: 30k_variables は 51 で 267 s、52 で 148 s）。 AOT が「-」のものはコンパイルしていない（Gemfile を使うベンチは railsbench・activerecord・shipit ほか一部だけ）。CRuby は --yjit-disable。 各値の右肩の番号はどの計測で取ったか（下の凡例）。
